# Product Requirements Document — PawnMarket

**Автор:** oleg
**Дата:** 2026-05-07

## Резюме

**PawnMarket** — специализированный маркетплейс для ломбардов, решающий две проблемы: фрагментированность предложения и отсутствие доверия покупателей к вторичному рынку залоговых товаров.

**Пользователи:** ломбарды (продавцы), нуждающиеся в онлайн-канале сбыта нереализованных залогов, и покупатели, ищущие ювелирные изделия, электронику и часы со скидкой при гарантии прозрачности.

**Стек:** Next.js (React) + TanStack React Query, моковые данные на бэкенде (MVP).

**Почему сейчас:** рынок ломбардов РФ — 302 млрд ₽/год, 94% залогов — золото. Нишевых маркетплейсов для ломбардов не существует. Онлайн-аудитория — 133+ млн. Нишевые маркетплейсы растут на 22% в год.

### Конкурентное преимущество

«Биография вещи» — каждый товар сопровождается проверенной историей: рейтинг прозрачности (0–100), таймлайн жизни предмета, оценка состояния ломбардом, фото. Ни Авито, ни Юла не предоставляют такой информации. Покупка «с рук» превращается в покупку с гарантией прозрачности.

## Инновации и отличия

### Инновационные области

- **«Биография вещи»** — уникальный подход к прозрачности на вторичном рынке: рейтинг прозрачности (0–100), таймлайн жизни предмета, проверенные данные от ломбарда. Аналогов на российском рынке нет.
- **Первый специализированный маркетплейс для ломбардов** — белое пространство в рынке на 302 млрд ₽/год. Рыночная инновация — первый игрок в пустой нише.

### Валидация

- Рейтинг прозрачности товаров ≥ 70/100 — «биография» воспринимается как ценность
- Конверсия просмотр → заказ ≥ 2% — прозрачность конвертирует в покупки
- Время добавления товара ломбардом ≤ 10 минут — инструмент доступен консервативной аудитории

### Риск-митигация

- «Биография» не работает → упростить до структурированного описания состояния
- Ломбарды не регистрируются → нулевая комиссия 30 дней + помощь с онбордингом (личный менеджер для первых 50 товаров)

## Критерии успеха

### Пользовательский успех

**Покупатели:**
- Находят нужный товар за ≤ 3 клика от главной до карточки
- Понимают «биографию вещи» с первого взгляда без дополнительной навигации
- Оформляют заказ за ≤ 2 минуты от корзины до подтверждения
- «Aha-момент» — полная история товара: «здесь всё прозрачно, можно доверять»

**Ломбарды:**
- Регистрация и первый товар за ≤ 10 минут
- Первый заказ в течение 7 дней после добавления товаров
- Управление заказами — ≤ 5 минут в день

### Бизнес-метрики (3 месяца)

| Метрика | Цель |
|---------|------|
| Зарегистрированные ломбарды | 10+ |
| Товаров в каталоге | 500+ |
| Заказов в месяц | 50+ |
| Конверсия (просмотр → заказ) | ≥ 2% |
| Возврат клиентов (ломбарды) | ≥ 70% повторных продаж |
| Комиссия | 1% с каждой сделки |

### Технические метрики

- Время загрузки страниц ≤ 2 сек (Next.js SSR/SSG)
- Lighthouse Performance Score ≥ 90
- Моковые данные покрывают 100% сценариев MVP
- Responsive: мобильные, планшеты, десктоп

### Измеримые результаты

- Средний рейтинг прозрачности ≥ 70/100
- NPS покупателей ≥ 40
- Доля доставка vs самовывоз — метрика для приоритизации логистики

## Пользовательские сценарии

### Сценарий 1: Анна покупает золотое кольцо

**Анна, 32 года, хочет купить кольцо на подарок маме.** Бюджет ограничен, в магазинах цены высокие. Подруга посоветовала ломбарды, но идти лично страшно — вдруг подделка.

Заходит на PawnMarket с телефона → «Ювелирные изделия» → фильтры «Кольца, Золото 585, до 15 000 ₽» → видит 12 результатов → на карточке зелёный бейдж «Рейтинг прозрачности: 85/100» → открывает: фото с ракурсов, состояние «Отличное (9/10)», таймлайн — «Оценено ломбардом "Золотой Ключ" 12.04.2026, фото чека оригинальной покупки» → проба подтверждена, цена ниже магазина на 40% → в корзину → доставка курьером → через 2 дня получает, точно как на фото.

### Сценарий 2: Дмитрий покупает ноутбук

**Дмитрий, 25 лет, студент. Нужен MacBook, новый не по карману.** На Авито страшно — нет гарантий, продавцы пропадают.

Ищет «MacBook Pro» → фильтрует по состоянию и цене → лот от «ТехноЛомбард», рейтинг прозрачности 72/100 → серийный номер указан, состояние «Хорошее (7/10)», дефекты: «маленькая царапина на крышке» с фото → самовывоз, ломбард в 20 минутах → бронирует, приезжает, осматривает → всё совпадает → покупает, оставляет отзыв.

### Сценарий 3: Сергей (ломбард) добавляет товары

**Сергей, 45 лет, владелец ломбарда «Золотой Ключ».** Компьютер на уровне «почта и Авито». 60 нереализованных залогов — золото и часы. На Авито — каждый товар вручную.

Регистрируется → «Добавить товар»: категория, фото, название, цена, состояние, описание → первый товар за 5 минут → за вечер 15 товаров → в кабинете статусы, просмотры → через 3 дня первый заказ → самовывоз → готовит товар → покупатель забирает → «Завершено» в кабинете.

### Сценарий 4: Админ управляет платформой

- Просмотр и подтверждение регистрации ломбардов
- Модерация товаров (одобрить/отклонить)
- Базовая аналитика: количество ломбардов, товаров, заказов
- Управление справочниками: категории, параметры фильтров, настройки доставки

## Область видимости и развитие

### Стратегия MVP

**Подход:** Problem-Solving MVP — доказать, что «биография вещи» создаёт доверие и конвертирует в покупки.

**Ресурсы:** 1 фронтенд-разработчик (Next.js, React), моковые данные.

### Phase 1 — MVP

**Must-Have:**
- Каталог с поиском и фильтрами (категория, цена, состояние)
- Карточка товара с «биографией» (рейтинг прозрачности, фото, описание, состояние, цена)
- Регистрация и кабинет ломбарда (добавление/редактирование товаров, заказы)
- Корзина и оформление заказа (доставка или самовывоз)
- Моковые данные, структурированные как реальный API

**Nice-to-Have (если позволит время):**
- Отзывы покупателей после получения товара
- Избранное / лайк товаров
- Уведомления ломбарда о заказах (email)

### Phase 2 — Post-MVP

- Платная экспертиза подлинности через партнёров
- Премиум-подписка для покупателей (ранний доступ к лотам)
- Лист ожидания / запросы покупателей
- Интеграция с 1С
- Аналитика продаж для ломбардов
- Эксклюзивность по территории

### Phase 3 — Vision

- Мобильное приложение (iOS/Android)
- Проверка серийных номеров через базы МВД
- Полноценная экосистема: верификация, аналитика рынка, B2B-инструменты

### Риск-митигация

| Риск | Тип | Стратегия |
|------|-----|-----------|
| «Биография» не вызывает доверия | Рыночный | A/B тест: карточка с биографией vs без, метрика — конверсия |
| Ломбарды не регистрируются | Рыночный | Нулевая комиссия 30 дней + личный менеджер для первых 50 товаров |
| Моковые данные не отражают реальность | Технический | Структура JSON идентична планируемому API |
| 1 разработчик — не успевает | Ресурсный | Nice-to-Have → 0, фокус на Must-Have |

## Функциональные требования

### Каталог и поиск

- FR1: Покупатель может просматривать каталог товаров с пагинацией
- FR2: Покупатель может искать товары по текстовому запросу
- FR3: Покупатель может фильтровать товары по категории (ювелирные изделия, техника, часы)
- FR4: Покупатель может фильтровать товары по цене (диапазон)
- FR5: Покупатель может фильтровать товары по состоянию (оценка ломбарда)
- FR6: Покупатель может сортировать результаты (по цене, дате, рейтингу прозрачности)

### Карточка товара — «Биография вещи»

- FR7: Покупатель может просматривать карточку товара: название, описание, цена, фото, категория
- FR8: Покупатель может видеть рейтинг прозрачности товара (0–100) с визуальным индикатором
- FR9: Покупатель может видеть оценку состояния товара (шкала ломбарда)
- FR10: Покупатель может видеть информацию о ломбарде-продавце (название, адрес самовывоза)
- FR11: Покупатель может видеть таймлайн жизни товара (оценка ломбардом, выставление на продажу)
- FR12: Покупатель может просматривать фотогалерею товара (несколько ракурсов)

### Корзина и заказ

- FR13: Покупатель может добавлять товары в корзину
- FR14: Покупатель может удалять товары из корзины
- FR15: Покупатель может выбрать способ получения: доставка или самовывоз
- FR16: Покупатель может заполнить контактные данные для заказа
- FR17: Покупатель может подтвердить заказ и получить подтверждение
- FR18: Покупатель может просматривать статус своих заказов

### Регистрация и аутентификация

- FR19: Покупатель может зарегистрироваться (email, пароль)
- FR20: Покупатель может войти в аккаунт
- FR21: Ломбард может зарегистрироваться (название, адрес, контакты, ИНН)
- FR22: Ломбард может войти в аккаунт

### Кабинет ломбарда

- FR23: Ломбард может добавлять товары (категория, название, описание, цена, состояние, фото)
- FR24: Ломбард может редактировать свои товары
- FR25: Ломбард может удалять/скрывать свои товары
- FR26: Ломбард может просматривать список своих товаров со статусами
- FR27: Ломбард может просматривать поступившие заказы
- FR28: Ломбард может менять статус заказа (принят, готов к выдаче, завершён)

### Панель администратора

- FR29: Админ может просматривать список зарегистрированных ломбардов
- FR30: Админ может подтверждать/отклонять регистрацию ломбардов
- FR31: Админ может модерировать товары (одобрить, отклонить)
- FR32: Админ может просматривать базовую аналитику (ломбарды, товары, заказы)
- FR33: Админ может управлять справочниками (категории, параметры фильтров)

### Общий UX

- FR34: Каталог и карточки товаров доступны без регистрации
- FR35: Сайт корректно работает на мобильных, планшетах и десктопе

## Нефункциональные требования

### Производительность

- NFR1: Страницы каталога загружаются за ≤ 2 сек при SSR
- NFR2: Переходы внутри SPA (кабинет, корзина) — ≤ 500 мс
- NFR3: Результаты поиска и фильтрации — ≤ 1 сек
- NFR4: Фото товаров — Next.js Image Optimization, lazy loading вне viewport
- NFR5: Lighthouse Performance Score ≥ 90 на страницах каталога
- NFR6: Bundle size главной страницы ≤ 200 KB (gzipped)

### Безопасность

- NFR7: Пароли хранятся в хэшированном виде (bcrypt)
- NFR8: Формы защищены от XSS (Next.js + санитизация ввода)
- NFR9: Авторизация через JWT или session tokens (подготовлено для реального API)
- NFR10: Роли разделены: покупатель, ломбард, админ — доступ только к своему функционалу
- NFR11: Моковые данные не содержат реальных персональных данных

### Доступность

- NFR12: WCAG 2.1 Level A
- NFR13: Семантическая HTML-разметка
- NFR14: Клавиатурная навигация для всех интерактивных элементов
- NFR15: Alt-тексты для всех изображений
- NFR16: Контрастность текста ≥ 4.5:1 (WCAG AA)
- NFR17: ARIA-атрибуты для кастомных компонентов, корректная работа с экранными читалками
